# 코딩 에이전트 하네스·멀티 에이전트 운영 조사 (2026-11-24)

D-60(초안)의 근거다. 출처 본문을 직접 읽고 정리했다. 수치는 원문에서 옮겼다. 교차 검증 투표는 하지 않았다.

## 확인된 것

### 1. 에이전트의 자기 검수는 결함을 거의 못 잡는다 (근거 가장 강함)
출처: Stack Overflow 블로그, "Your coding agent shouldn't grade its own homework" (Momentic CTO, 2026-11-13)
- AI가 쓴 단위 테스트 1,000개를 사람이 감사했다. 쓸모 있는 검증은 9.6%였다. 의미 없는 테스트가 약 1/3, 중복이 22.8%, 과도한 mock이 22.4%였다.
- 111개 과제에서 테스트 작성을 허용한 에이전트와 금지한 에이전트를 비교했다. 성공률은 65.3%와 66.2%였다.
- 에이전트의 테스트는 구현과 같은 가정을 담는다. 그래서 "만들어야 했던 것"이 아니라 "만든 것"을 검사한다.
- 맥락이 길어지고 실패가 반복되면 검증보다 "완료" 선언으로 기운다(글이 인용한 Chroma Context Rot 연구, Anthropic 연구).
- 대응: 독립 QA 에이전트를 둔다.
  - 요구사항과 실행 중인 앱만 받는다. 구현 내용과 대화 이력은 받지 않는다.
  - 실제 브라우저·기기에서 검증한다.
  - 구현 에이전트는 검수 기준을 바꿀 수 없다.
  - 자기 출력 선호 편향 때문에 5개 회사의 모델을 섞는다.
  - 결과: Codex·Claude Code가 스스로 찾은 것보다 버그를 3~5배 더 찾았다. 테스트 도구 회사의 자사 벤치마크다.

### 2. 에이전트에게 TDD를 시켜도 효과가 불분명하다
출처: martinfowler.com, "TDD in the agent loop" (소규모 실험)
- TDD 쪽 결과가 약간 나빴다. mutation 점수는 의미 있는 차이가 없었다.
- 에이전트는 red 단계를 자주 건너뛰고, 구현을 먼저 쓰고, 다음 단계를 앞질러 구현한다.
- 테스트를 먼저 썼는데도 구현 출력을 그대로 기대값으로 쓰는 동어반복 테스트가 나왔다.
- "red는 누군가 왜 red인지 확인할 때만 증거다."

### 3. CI 통과는 안전의 증거가 아니다
출처: Vercel, "Agent responsibly" (2026-03-30)
- 테스트는 통과했지만 운영을 망가뜨린 사례: 전체 행 스캔 쿼리, 재시도 폭주, TTL 없는 캐시.
- 대응은 리뷰를 늘리는 것이 아니라 인프라 쪽이다.
  - canary 배포와 자동 중단·되돌리기
  - 문서 대신 실행 가능한 가드레일(도구·skill)
  - 운영 불변식을 계속 검증하는 읽기 전용 감사 에이전트
  - 결함이 커밋 단계에서 잡혔는지, 운영으로 새어 나갔는지의 비율 측정

### 4. 사람은 루프 안이 아니라 루프 위에 있다
출처: martinfowler.com, Kief Morris, "Humans and Agents in Software Engineering Loops" (2026-03-04); Thoughtworks, "How far can we push AI autonomy in code generation?"
- 사람이 한 줄씩 검수하면 병목이 된다. 사람의 역할은 하네스(명세·품질 검사·워크플로 지침)를 만들고 고치는 것이다("Harness Engineering").
- 역할별 에이전트 파이프라인(요구분석 → 설계 → 계층별 생성 → E2E → 리뷰)은 단순한 앱은 만들었다. 복잡도가 올라가자 요구에 없는 기능이나 요구 누락이 생겼다. "생성된 테스트는 누가 검수하나"는 풀리지 않았다.

### 5. 생산성 체감은 믿을 수 없다
출처: METR 2025-07-10 연구, 2026-02-24 업데이트
- 2025년 초, 숙련 오픈소스 개발자가 AI를 쓰면 19% 더 느렸다. 본인들은 20% 빨라졌다고 믿었다.
- 2026년 재측정에서는 속도 향상 신호가 보였다. 하지만 METR는 선택 편향 때문에 신뢰할 수 없다고 보고 연구 설계를 바꾸는 중이다.

### 6. 하네스 기본 (Anthropic, "Steering Claude Code: skills, hooks, rules, subagents")
- CLAUDE.md는 권고일 뿐이다. 반드시 지켜야 할 규칙은 hook(PreToolUse exit 2)으로 막는다.
- managed settings는 로컬 설정으로 덮어쓸 수 없다.
- 서브에이전트는 메인 세션에 최종 메시지만 돌려준다. 그 요약은 증거가 아니다.
- CLAUDE.md는 200줄 이하로 두고, 담당자를 정하고, 코드처럼 리뷰한다.
