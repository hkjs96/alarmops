## 5. 순위와 이유

1. **A** — 5초 테스트 10/10. 화면 이동과 뒤로 가기에서 스코프가 가장 예측 가능하다. 범위 밖 사고 경고가 전 화면에 있다. 고정·최근·`Ctrl K`로 전환이 빠르다. 약점은 "전체" 상태에서의 MSP 기본값 편집과 색 없는 텍스트 바의 낮은 식별력이다.
2. **C** — 5초 테스트 10/10이고 고객 식별은 A보다 강하다. 감사자와 소연에게 가장 설득력 있다. 다만 MSP 운영자는 야간에 여러 고객을 오가는데 전환 단계가 많고 헤더가 두껍다. 색·이니셜은 30곳이 넘으면 겹친다.
3. **D** — 전 고객 목록과 패널 딥링크는 전문가에게 가장 좋다. 그러나 화면 스코프 표시가 가장 약하고(5/10), 칩·패널 불일치는 네 안 중 가장 구체적인 사고 경로다.
4. **B** — 관문 자체는 편집 방지에 효과가 있다. 그러나 관문을 지나면 A와 같은 고정 스코프가 되면서 A의 안전장치(고정 바, 범위 밖 경고)는 없다. 표시도 세 가지로 갈린다.

## 6. 추천 설계 (A 뼈대 + C 띠 + D 고객 열·패널 머리말 + B 관문은 생성에만)

### 구성

| 요소 | 가져올 곳 | 내용 |
|---|---|---|
| 상단 스코프 바 | A | 내비게이션 바로 아래 한 줄. `고객 › 프로젝트 › 서비스` 세 칸. 모든 화면, 모든 폭에서 같은 자리. |
| 고객 식별 | C | 고객이 선택되면 바에 고객 색 띠와 이니셜 아바타를 입힌다. "전체"는 무채색 `ALL`. 색은 보조 수단이고 이름이 항상 같이 나온다. |
| 목록의 고객 열 | D | 스코프가 "전체"이거나 고객 단계일 때 표에 고객·프로젝트›서비스 열을 둔다. 좁혀지면 중복 열은 숨긴다. |
| 편집 머리말 | D | 편집 카드·패널 맨 위에 `SCOPE · 대상 종류 / 전체 경로`. APPLIES TO 블록은 유지한다. |
| 생성 관문 | B | 스코프 없이 "새로 만들기"를 누를 때만 `Choose a scope first`. 조회는 막지 않는다. |
| 범위 밖 경고 | A·C | 스코프가 걸린 모든 화면에 `N open outside this scope`. |
| 전환기 | 공통 | `Ctrl K`, 고정·최근·내 고객 묶음, 결과는 항상 전체 경로. |

### 규칙

1. **표시 위치**: 현재 스코프는 스코프 바 한 곳에만 표시한다. 필터 칩, 헤더 드롭다운 같은 두 번째 표현을 만들지 않는다.
2. **항상 전체 경로**: 프로젝트·서비스 이름은 단독으로 쓰지 않는다. 버튼·토스트·패널 제목·감사 로그 모두 `Daon Retail › Commerce › Checkout` 형식이다. (`Create for Checkout` → `Create for Daon Retail › Commerce › Checkout`)
3. **조회에는 스코프가 필요 없다**: 사고, 모니터링, 페이징 현황, 점검 목록은 "전체"에서 바로 보인다.
4. **쓰기에는 스코프가 필요하다**: 고객 소유 대상(페이징 단계, 고객 사람, 점검 창, 고객 기본 임계치)은 고객이 정해져야 편집 화면이 열린다. 스코프 없이 만들면 관문에서 먼저 고른다.
5. **MSP 전체 변경은 분리한다**: 14개 고객 전체 기본 임계치는 "전체" 화면에 입력란을 그대로 두지 않는다. 별도 진입 → 미리보기 → 영향받는 고객 수를 적은 확인 단계를 거친다.
6. **편집 대상 = 화면 스코프**: 패널·카드가 여는 대상이 스코프 바와 다르면(상속 원본을 여는 경우 등) 열기 전에 스코프 바를 그 대상으로 옮기거나, 패널에 "화면은 Checkout, 편집 대상은 Mirae Pay 전체"라고 경고 띠를 띄운다. 두 스코프를 말없이 같이 두지 않는다.
7. **저장 문장**: 저장 버튼 바로 위에 APPLIES TO(대상, 프로젝트·서비스 수, 영향받지 않는 것)를 붙여 둔다. 스크롤해도 버튼과 함께 보이게 한다.
8. **되돌리기**: 저장 토스트에 실행 취소를 넣는다. 여러 프로젝트에 걸치거나 고객 전체·MSP 전체에 적용되는 저장은 대상 이름을 다시 적은 확인 단계를 거친다.
9. **고정 스코프 경고**: 스코프가 걸려 있으면 범위 밖 미해결 사고 수를 모든 화면에 표시한다. 탭 배지는 "범위 안/전체"를 구분해 적는다. SEV-1은 스코프와 무관하게 알린다.
10. **URL**: 스코프는 URL에 넣고 고객은 경로에 둔다(`/c/daon/paging?project=commerce&service=checkout`). 패널도 URL에 넣되, 패널을 닫을 때는 히스토리를 새로 쌓지 않고 뒤로 간다.
11. **휴대폰**: 스코프 바는 한 줄 고정, 길면 가운데를 줄이고(`Daon … › Checkout`) 누르면 전체 경로가 보인다. 칩처럼 가로로 잘리는 표현은 쓰지 않는다. 조작부 높이는 44px 이상으로 한다.
12. **고객 포털**: 고객 단은 선택기가 아니라 고정 라벨이다. 다른 고객 이름, 고객 수, 범위 밖 사고, 고객 전환 버튼, 고객 열은 렌더링하지 않는다. MSP 직원 행의 `12 customers`도 숨긴다.
