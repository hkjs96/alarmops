## 항목

| 4 | 권고 | 핸들러 읽기와 쓰기 사이에 (SQL·수동 작업 등으로) 상태가 이미 목표 값이 되면 저장소가 예외를 던져 500이 된다 | **반영** — 저장소가 `NOOP`을 돌려주고 핸들러는 같은 상태 요청과 똑같이 200으로 답한다(아무것도 쓰지 않음). 계약 테스트로 고정 |

## 남은 위험

- 아웃박스가 없어 커밋과 발행이 원자적이지 않다. 복구는 같은 `TERMINATED` 요청 재전송(수동)이다.
- 실제 Postgres(`TEST_DATABASE_URL`)에서 `FOR UPDATE` 직렬화와 RLS 정책은 확인하지 못했다(pglite만).
- seed 번호 가드는 한국 번호(`010-0000-xxxx`)만 본다. 다른 국가의 시험용 번호는 막지 않는다.
- 감사 행의 `reason`·`detail`은 ADMIN이 쓴 자유 문장이다. 비밀값을 적지 않도록 화면 안내가 필요하다.
