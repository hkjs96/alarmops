# 구현 지시 체크리스트 (11/26~27 PR #153~#163에서 나온 함정)

허브는 이슈를 에이전트에 배정할 때 해당 영역 항목을 지시문에 그대로 붙인다. 검토자(security·docs-auditor)도 같은 목록으로 본다. 목록에 넣는 기준은 "검토에서 걸려 PR을 한 번 더 돌게 한 것"이다.

## 사람이 실행하는 스크립트 (Windows Git Bash)
- [ ] **경로 변환**: `/`로 시작하는 인자(`--path-prefix /aws-reserved/`, `/aws/lambda/...`)는 Git Bash가 Windows 경로로 바꾼다. 스크립트에서 `MSYS_NO_PATHCONV=1`을 쓰거나 그런 인자를 피한다. 사람에게 주는 명령에도 붙인다.
- [ ] **`\r`**: Windows `aws.exe`의 `--output text` 줄 끝에 `\r`이 붙는다. 변수에 담는 모든 출력은 `tr -d '\r'`을 거친다. 자격증명에 섞이면 `Invalid header value` 오류에 토큰이 찍힌다(11/26 실제 노출).
- [ ] **빈 환경변수**: `AWS_PROFILE=` 처럼 비우면 "빈 이름 프로필"을 찾는다. 지울 때는 `env -u AWS_PROFILE` 또는 `unset`.
- [ ] **종료 코드**: `$?`·`${PIPESTATUS[@]}`는 바로 다음 줄에서 읽는다. `echo` 뒤에 읽으면 항상 0이다.
- [ ] **환경변수 오염**: `AWS_ENDPOINT_URL*`·`AWS_CONFIG_FILE`·`AWS_SHARED_CREDENTIALS_FILE`·`AWS_CA_BUNDLE`이 설정된 터미널을 어떻게 다룰지 정한다(거부 또는 안내).
- [ ] **정리 순서**: 정리 명령을 사람에게 실측 명령과 같은 블록으로 주지 않는다. 먼저 정리하면 다음 단계가 AccessDenied로 실패해 원인을 헷갈린다. 스크립트는 `trap`(EXIT/INT/TERM/HUP)으로 정리한다.

## AWS CLI 인자
- [ ] **리스트 인자 JSON 해석**: 리스트형 인자(`--alarm-names`, `--tag-keys` 등)의 값이 `[`나 `{`로 시작하면 CLI가 JSON으로 읽는다. 엔진 알람 이름은 `[{타입}] …`이다. 이런 값은 JSON 배열(`'["이름"]'`)로 넘긴다(11/27 #163, awscli 1.46.3에서 재현).
- [ ] **공백·대괄호 이름**: 모든 인자를 따옴표로 감싼다.
- [ ] **오류 출력**: aws 오류 메시지에 자격증명이 섞일 수 있다. 사람에게 보이는 출력은 마스킹을 거친다.

## 마스킹
- [ ] **데이터 경로와 출력 경로를 나눈다**: 스크립트가 값으로 쓰는 출력(`aws_r` stdout)에는 확실한 자격증명 모양만 가린다. 넓은 휴리스틱은 사람에게 보이는 출력에만 쓴다. 넓은 규칙이 긴 알람·큐·역할 이름을 `****`로 바꿔 판정을 조용히 틀리게 한 적이 있다(#160).
- [ ] 회귀 테스트에 50자 넘는 mixed-case 이름(알람·큐·`AWSReservedSSO_…`)을 넣는다.

## IAM 실측
- [ ] **최종 일관성**: 정책을 붙이거나 바꾼 직후 결과를 판정하지 않는다. 옛 정책이 남아 있는지, 새 정책이 반영됐는지 카나리로 확인하고, 판정에 쓰는 측정은 두 번 해서 같을 때만 쓴다(#162).
- [ ] **시험 대상 오염**: 시험 알람·리소스는 시작할 때 지우고 만든 뒤 상태(태그 등)를 확인한다.
- [ ] **판정 순서**: 앞 항목의 실패가 뒤 항목의 판정을 오염시키지 않게 순서를 잡는다(#160 (f)).
- [ ] 문서에 없는 AWS 동작(예: 생성 시 `aws:ResourceTag` 평가)은 추측으로 정책을 짜지 말고 실측 도구를 먼저 만든다(#162).

## 문서와 스크립트
- [ ] 사람이 보는 문서의 명령·행 이름·셀 값·종료 코드·정리 대상이 스크립트 출력과 **글자 그대로** 같다. 스크립트 문구를 바꾸면 같은 PR에서 문서를 고친다.
- [ ] 화면에 나오는 안내와 문서 안내가 반대로 말하지 않는다(#162 카나리 메시지).
- [ ] 실행 명령은 붙여 넣으면 바로 돌아가는 형태(`bash infra/scripts/...` 경로 포함, `aws sso login` 포함)로 쓴다.
- [ ] 사람 작업이 바뀌면 GO-LIVE의 본 절차와 "막혔을 때" 표를 둘 다 고친다. 한쪽만 고치면 서로 반대로 말한다.
- [ ] 고객에게 요청하는 단계(7-3 등)에 새 고객 작업·안내를 넣는다. 리허설 단계에만 넣지 않는다.

## 검토 진행
- [ ] 문구 수준의 docs 지적은 허브가 직접 고치고, 바뀐 부분만 docs-auditor에게 다시 확인받는다.
- [ ] 막지 않는 권고는 PR에 넣지 않고 바로 후속 이슈로 돌린다.
- [ ] **테스트 실행 범위(11/27 사용자 결정)**: 구현 에이전트는 로컬에서 바꾼 부분과 관련된 테스트만 돌린다(새 테스트는 먼저 실패를 확인). 영역 전체 실행은 CI가 PR마다 한다. 수정 왕복마다 로컬 전체(infra 약 4~5분)를 다시 돌리지 않는다. CI가 실패하면 원인을 찾아 고친다(건너뛰기·끄기 금지).
- [ ] 허브는 CI가 통과한 head에서만 병합한다. 에이전트가 보고한 테스트 결과는 증거로 쓰지 않는다(D-60).
